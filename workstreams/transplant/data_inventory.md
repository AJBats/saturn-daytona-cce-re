# DUSA-port data inventory & homing design

Every distinct data address the ported player pipeline reads or writes, **in
contiguous DUSA address order**, with an RE purpose guess and a suggested home.
Factual skeleton (address / refs / current home) is generated by
`python3 tools/dusa_data_inventory.py`; extents measured from APROG; purpose +
suggested-home are RE judgment. Supersedes the per-pointer view in
`data_homing_plan.md` §4–5 (decision there is now made: **model A, whole
contiguous regions homed together**).

## The rule (simple, by design)

> **Small, constant, hot physics tables → race.bin** (fast memory, lives with
> the code).
> **Everything big (surface curves, the trig LUTs) and everything runtime-mutable
> (pads, buttons, opponents, scratch, dispatch) → COL.**

Mechanically that lines up with provenance + size:
- **APROG-image static, read-only, ≤~1 KB** → race.bin.
- **APROG-image static but > race.bin headroom** (only the 8.7 KB surface block) → COL.
- **Written, or work-RAM/LWR-resident** → COL.

We carry each *contiguous DUSA region as one block* (never split a region across
race.bin/COL), so `base + index*stride` indexing and table adjacency are
preserved by construction. (F17C disassembly confirmed indexing is intra-table
via independent per-table pointers — see `data_homing_plan.md` §5 — so the only
hard requirement is "don't split a region," which this honors.)

## Budget consequence

**race.bin (new static embeds):** drift+trac 1044 B + gear region ~84 B + F270 bounds (already present)
≈ **~1.13 KB**. Current headroom 8.95 KB → **~7.8 KB left**. Comfortable.
Moving trac/gear/anim *out* of COL also **returns ~0.95 KB** to the COL fixed block.

**COL (new):** surface block **8912 B** is the only meaningful addition (work-RAM
globals are a few dozen bytes total). Net COL fixed-block change ≈ **+7.9 KB**;
binding track Three Seven free 14.4 KB → **~6.6 KB**. Fits. (cos 16 KB + atan 8 KB
already reserved there.)

## Decision (made 2026-06-17): surface → COL now

The natural boundary: *every* other static table fits race.bin; surface alone
(8912 B) exceeds the 8.95 KB headroom once the ~1.1 KB of small tables are in.
**Surface → COL** (the pre-authorized "out of room → COL" clause), sitting beside
cos/atan. Boot stays on the critical path; promoting it to race.bin later (after a
dead-code batch) is a 1-line home-map change if profiling ever justifies it.

**Operating principle (applies to the whole port):** if ported DUSA code
references a region, we carry that *whole contiguous region* to its home as-is,
byte-faithful. Refining a region's true semantics/extent (e.g. surface
global-vs-per-track) is deferred — placement correctness does not depend on it;
only a later cross-track dedup optimization would. Don't rabbit-hole; we can pull
a block apart later.

## Implementation order (once surface decided)

1. Build the **homing map** in `gen_disc_data.py` (`{DUSA addr → home}`): COL slots
   for work-RAM + surface(if A) + ECF2 flag; race.bin data shims for drift+trac +
   gear region.
2. `emit_asm` auto-reloc: any pool word whose value is in the map → emit the
   home symbol/macro instead of the literal. Auto-generate allowlists.
3. New race.bin data shims (real APROG bytes): `dusa_dat_physics.c` (drift+trac),
   `dusa_dat_gear.c` (gear region). Point F17C's F270-bounds literal at `.Lf270_bounds`.
4. Re-home gear-ratio/anim/trac/drift from COL → the race.bin shims (undo prior COL
   homes; drop those `gen_disc_data`/`dusa_state.h` entries).
5. Populate COL real data: surface(if A), cos, atan, plus seed values for the
   written work-RAM slots.
6. `audit_dusa_data.py` → 0; then flip the tick to ECF2 and boot.
